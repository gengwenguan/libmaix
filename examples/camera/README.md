# Camera 视频监控例程

基于 libmaix 框架的完整视频监控系统，运行在 M2dock 开发板上。实现了摄像头采集、H264 视频编码、Opus 音频编码、实时网络传输和本地文件存储等功能。

## 功能特性

- 实时视频采集与显示（30 FPS）
- H264 硬件编码
- Opus 音频编码
- TCP 网络实时传输
- 本地文件存储（支持快进快退）
- OSD 叠加（IP地址、时间显示）
- 多客户端同时预览

## 核心模块说明

### 1. 主程序 (main.cpp)

提供两种摄像头采集方式：

| 方式 | 性能 | 采集格式 | 特点 |
|------|------|----------|------|
| 方式1 | ~8 FPS | RGB888 | 使用 `capture_image` 接口，需手动缩放 |
| 方式2 | ~30 FPS | NV21 | 使用 `capture` + `libmaix_vo` 接口，硬件加速 |

**推荐使用方式2**，核心流程：

```cpp
// 1. 创建摄像头和显示设备
struct libmaix_cam* m_camera = libmaix_cam_create(0, kCamInW, kCamInH, 1, 0);
struct libmaix_vo* m_vo = libmaix_vo_create(kCamInW, kCamInH, 0, 0, kDispW, kDispH);

// 2. 获取帧缓冲区
void *frame = m_vo->get_frame(m_vo, 0);
m_vo->frame_addr(m_vo, frame, &vir, &phy);

// 3. 摄像头直接采集到缓冲区（零拷贝）
m_camera->capture(m_camera, (unsigned char *)vir[0]);

// 4. 使用 OpenCV 叠加 OSD 信息
cv::putText(gray, ip_address, ...);
cv::putText(gray, datetime, ...);

// 5. 显示和编码传输
m_vo->set_frame(m_vo, frame, 0);              // 显示到屏幕
pterminal->InputNv21((unsigned char*)vir[0]); // 送编码传输
```

### 2. 终端管理类 (C_Terminal)

整个系统的**核心调度器**，采用观察者模式设计：

```cpp
class C_Terminal : public C_H264Enc::C_Listener,      // 监听编码器
                   public C_TcpServer::C_Listener,    // 监听TCP服务器
                   public C_FileMng::C_Listener,      // 监听文件管理
                   public C_OpusEnc::C_Listener       // 监听音频编码
```

**数据流向：**

```
摄像头采集(NV21/YUV420SP) 
    │
    ▼
C_Terminal::InputNv21()
    │
    ▼
C_H264Enc::InputData() ──→ 硬件编码 ──→ OnOutputH264()
    │
    ├──→ C_TcpServer::SendH264()    (网络传输)
    │
    └──→ C_FileMng::InputFileData() (本地存储)
```

### 3. H264 编码器 (C_H264Enc)

**编码参数配置：**

| 参数 | 值 | 说明 |
|------|-----|------|
| 码率 | width × height | 动态码率 |
| 帧率 | 30 fps | - |
| 关键帧间隔 | 60 秒 | - |
| Profile | Main Profile | - |
| 码率控制 | VBR | 动态码率 |
| QP 范围 | 5-40 | - |

**强制 I 帧机制：**
- 新客户端连接时强制编码 I 帧（快速出图）
- 新文件创建时强制编码 I 帧（保证文件可播放）

### 4. TCP 服务器 (C_TcpServer)

**协议设计：**

```
┌────────────────┬────────────┬──────────────┐
│ 4字节长度      │ 1字节标志  │ N字节数据    │
│ (网络字节序)   │            │              │
└────────────────┴────────────┴──────────────┘
```

**标志位定义：**
- `0x80`：视频数据（H264）
- `0x00`：音频数据（Opus）

**特点：**
- 端口：56050
- 支持多客户端同时连接
- 自动检测断开的客户端并清理

### 5. 文件管理 (C_FileMng)

**文件存储策略：**

| 配置项 | 值 |
|--------|-----|
| 存储路径 | `video/` 目录 |
| 最大文件数 | 10 个 |
| 单文件最大 | 1 GB |
| I帧索引 | 100 个位置（均匀抽取） |

**文件格式：**

```
┌─────────────────────────┬───────────┬───────────┬─────┐
│ I帧索引头               │ 数据块1   │ 数据块2   │ ... │
│ (8字节 × 100)           │           │           │     │
└─────────────────────────┴───────────┴───────────┴─────┘

每个数据块：
┌────────────┬────────────┬──────────────┐
│ 4字节长度  │ 1字节标志  │ N字节数据    │
└────────────┴────────────┴──────────────┘
```

### 6. Opus 音频编码 (C_OpusEnc)

**音频参数：**

| 参数 | 值 |

| 采样深度 | 16 bit |
| 通道数 | 1（单声道） |
| 码率 | 64 kbps |
| 帧长 | 20 ms（960 samples） |

## 关键配置参数

## 使用说明

### 实时预览

1. 连接 TCP 端口 **56050**
2. 先接收 4 字节长度（网络字节序）
3. 接收 1 字节标志位（0x80=视频，0x00=音频）
4. 接收实际数据

### 文件回放

1. 连接 TCP 端口 **56060**
2. 发送控制命令（单字节）
3. 接收历史视频数据

### 信号处理

程序支持以下信号优雅退出：
- `SIGINT` (Ctrl+C)
- `SIGTERM`
- `SIGTSTP`
- `SIGQUIT`

## 性能优化

1. **零拷贝采集**：使用 `libmaix_vo` 直接获取物理地址，摄像头 DMA 直接写入
2. **硬件编码**：利用芯片内置 H264 编码器，降低 CPU 占用
3. **VBR 动态码率**：静态画面自动降低码率，节省带宽和存储空间
4. **双缓冲机制**：编码器内部使用双缓冲，提高吞吐量

- IoT 摄像头

- 智能门铃


## 注意事项

1. 摄像头采集分辨率必须为 16 的整数倍
2. M2dock 显示屏分辨率固定为 240×240
3. 程序启动时会等待 8 秒让设备获取 IP 地址和时间同步
4. 文件存储目录 `video/` 会自动创建
